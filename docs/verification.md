# 实现选择与验收

验收日期：2026-10-05。

## 需求中需要取舍的地方

1. **容器启动后打开宿主网页**：Linux 容器不能直接操作 macOS 图形会话。提供当前用户 LaunchAgent 浏览器助手，由一键启动器安装；根据健康接口的实例编号，每次容器启动打开一次前端。服务随容器启停，助手仅检查本机健康接口，可独立卸载。
2. **安装 skill 后每项任务都通知**：仅复制 SKILL.md 不能强制所有 Agent 自动选用。导出包附显式安装器，同时安装 skill 与受管理的 Codex AGENTS.md / Claude CLAUDE.md 通知规则，保留现有配置，支持卸载。没有在开发时擅自安装到当前 Agent。
3. **等待接口和超时**：创建请求立即返回持久 ID，后续使用最长 25 秒的长轮询持续等待，避免单次 HTTP 长连接跨越全部等待期。回复默认期限 5 分钟，API 支持 30 秒到 24 小时。按邮箱服务器接收时间判断及时回复；截止后最多 30 秒核对最后一批邮件。超时不等于同意，Agent 按原有权限与风险决定继续或暂停。
4. **轻量依赖与凭据**：Python 标准库 + SQLite + 原生前端，无 pip/npm 运行依赖。SMTP/IMAP 必须使用 TLS，使用邮箱服务商的授权码或应用专用密码；不提供 OAuth 流程。凭据保存在权限受限的本机数据卷，不声称静态加密。
5. **异常重启与重复邮件**：HTTP 使用幂等键。SMTP 没有可用的端到端 exactly-once 协议，发送中崩溃后将结果标为未知并保存可读解释，不盲目重复发送。诊断记录原子写入终态，不会作为邮件发送。
6. **历史收件边界**：完整历史记录长期保存；后台自动收取回复覆盖最近 30 天最多 300 个对话，始终优先最多 100 个活跃请求。晚到回复单独标记，已超时的请求不会被重新激活。自动回复、非目标发件人和无关联邮件不会作为用户决策。

## 网易客户端身份声明修复

真实环境暴露了原模拟客户端遗漏的类型差异：Python `imaplib.capabilities` 返回字符串，而旧代码只比较字节类型的 `ID`。因此跳过客户端身份声明，网易在打开 INBOX 时返回 `Unsafe Login`，被误报为文件夹不可用。

修复同时兼容字符串和字节形式的能力标识，并将安全策略拒绝与文件夹错误分开解释。新增回归测试验证身份声明必须发生在打开收件箱之前；TLS 协议回环服务也会拒绝未声明身份的连接。修复后实际账号连接与只读搜索通过。排查期间一次证书校验失败，后续校验成功；没有关闭证书校验。

用户随后明确要求安装已下载的 skill，已使用本地安装器安装到 Codex 并启用受管理的全局通知规则。令牌未写入本仓库。

## 回复漏收修复

真实邮箱中已存在回复，但网易的 IMAP SUBJECT 搜索没有返回带 MIME 编码中文主题的邮件；部分回复也没有线程引用头。改为按日期检索候选，在本机解码邮件头并匹配唯一请求标记。每轮最多读取 100 个头部，大邮箱同时检查最近 50 封并轮转更早的 50 封，避免历史回复一直被新邮件遮住。已下载且保存的回复不会重复下载正文或重复记录。

同时修复未知提供商引用 ID 阻断精确主题匹配、FETCH 正文后返回 INTERNALDATE 时丢失日期，以及中文发件人置前／含 HTML 实体的引用分隔符处理。已知请求之间的引用冲突仍拒绝；邮件自身的 Date 和正文不能伪造接收时间。

实际回复来自与目标邮箱不同的发件账号，因此单独保存为「回复未采纳」，在列表、详情和等待提示中解释原因。它们不修改有效 reply 或等待状态。用户尚未授权额外的回复地址，继续只允许原目标邮箱。无需修改目标配置即可解决邮件客户端选错发件账号的问题：从目标邮箱账号直接回复。

已从真实邮箱恢复此前的 3 封回复；重建容器后仍保留，原超时状态不复活。浏览器确认提示和回复内容可见。新增协议回环验证中文主题、无线程头、服务商搜索失效及 INTERNALDATE 位于正文后的组合；80 项 Python 测试及前端行为测试通过。

另用实际 TLS 握手复现网易节点偶发返回与 imap.163.com 不匹配的证书（OpenSSL verify_code=62），现单独显示 TLS_HOSTNAME_MISMATCH 和排查提示。完整证书校验下的其他连接及后续后台轮询正常；未关闭或放宽 TLS 校验。此服务商／网络问题仍可能导致某次轮询失败，后台会继续重试。真实目标邮箱的一次新的及时回复仍是完整用户往返验收的剩余步骤。

## 扫码确认后未登录的反馈修复

用户测试号扫码确认后，真实微信页面返回「登录失败」，未建立网页登录会话。旧 adapter 丢弃错误细节，bridge 自动恢复又叠加 load 监听器，造成重复绑定并关闭页面。现保留微信 XML 返回码为 WECHAT_LOGIN_REJECTED，清除失效二维码，并将失败作为持久诊断显示；后续健康检查不覆盖这一原因。恢复时移除旧内部 load 监听器，并合并同一页面的并发注入，防止未处理异常使容器退出。前端区分等待扫码、已扫码待确认和手机确认后的登录过程。

完整 Python 测试 135 项（本机跳过一项 SDK 测试）；Docker Python 3.10 内 22 项传输测试全部通过，包含真实 SDK 接收错误事件且仅转发错误码，不泄露登录页面或凭据。Node/前端三组测试通过。用户再次扫码确认后，实际捕获微信返回码 1203，并在 API 与持久诊断中核实 WECHAT_LOGIN_REJECTED；容器仍健康且未重启。该返回码表示微信拒绝当前 Web 登录环境，尚未建立登录会话。它不能单独区分账号的 Web 登录资格和 Wechaty 所用环境的兼容性，下一步可用同一账号在官方 wx.qq.com 验证。
